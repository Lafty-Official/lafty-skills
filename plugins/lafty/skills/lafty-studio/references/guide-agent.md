### 9-1. 지킬 규칙

1. 결과는 항목 단위로 내요. 항목 이름은 스튜디오 이름이나 규격 이름을 그대로 써요. 규격에 없는 항목을 만들지 않고, 필요한 내용은 가장 가까운 항목에 산문으로 넣어요.
2. 3·4장 표의 한도(글자 수, 개수, 고를 수 있는 값)를 지켜요. '권장'은 벗어나도 되지만 이유가 있어야 해요.
3. 플레이어를 가리키는 자리에는 `{{{PLAYER_NAME}}}`만 써요. `{{user}}`, `{{char}}`, `{player}`는 쓰지 않아요. 플레이어의 이름, 나이, 과거, 감정, 결정, 대사를 정하지 않아요.
4. 에피소드의 글에서 메인과 서브는 캐릭터 이름 항목과 똑같은 이름으로 써요.
5. 첫 인사, 만남의 첫 메시지는 물음표로 끝내지 않아요.
6. 앞일(반전, 비밀, 결말)은 비밀, 이벤트 설정, 연출 안내, 일어나는 일, 에필로그 방향에만 써요. 늘 가는 항목, 화면 항목, 제목, 예고 문구에는 쓰지 않아요(1-3 표).
7. 플레이어만 아는 일은 프롤로그에, 둘 다 아는 일은 시작 상황에 써요.
8. '일어나는 일'은 원문으로 확인할 수 있는, 눈에 보이는 행동 하나예요. 이야기를 푸는 결정적인 행동은 플레이어 몫으로 남겨요.
9. 제작자 선택지는 플레이어가 그대로 보낼 수 있는 60자 이내의 말이에요.
10. 갈림길마다 표시 없는 기본 경로를 둬요. 마지막 챕터를 끝내는 이벤트에만 엔딩을 붙여요.
11. 상태창 형식, 글자 수 강요, 출력 형식, 그림 코드, 'AI처럼 굴지 마' 같은 지시를 어느 항목에도 쓰지 않아요.
12. 첫 장면은 서술 문단과 `[이름:표정] "대사"` 줄로 쓰고, 표정은 그 인물의 표정·상황 목록에 있는 이름만 써요.
13. 하루 일과의 요일은 0=월, 1=화, 2=수, 3=목, 4=금, 5=토, 6=일이에요. 시각은 24시간 `HH:MM`이고, 짧은 항목을 넓은 항목보다 위에 두어 하루를 덮어요.
14. 형용사 라벨 대신 조건과 반응으로 써요. 가게, 동네, 사람 이름과 시간, 기간 같은 숫자를 줘요.
15. 작품 등급과 8장을 지켜요. 2차 창작은 전체·15세로만 써요.
16. 제작자가 주지 않았는데 지어낸 설정(이름, 과거, 숫자)은 '지어낸 것'으로 따로 적어 제작자가 확인하게 해요. (가)는 결과 끝에, (나)는 JSON 밖의 답 본문에 적어요.
17. 그림은 그리지 않아요. 이미지를 만드는 도구가 있어도 같아요. 그 대신 자리마다 사진 탭에 붙여 넣을 단부루 태그를 내요(5-5). 영어 소문자로 띄어 쓰고, 품질 태그와 이름, 나이 숫자, 실사풍 태그는 쓰지 않아요. 2차 창작만 원작 캐릭터의 이름 태그를 써요. 태그는 전체 이용가까지만 쓰고, 19 그림은 제작자가 사진 탭에서 그려요.

### 9-2. 결과 모양

둘 중 하나를 골라요.

**(가) 항목별 글:** 사람이 스튜디오에 붙여 넣기 좋아요. 제목에 탭과 항목을 적어요.

```markdown
## 캐릭터 › 기본 › 핵심 설정
남의 시계는 초 단위로 맞추면서 자기 하루는 대충 흘려보내는 사람.

## 캐릭터 › 성격 › 행동으로 드러나는 결점
- 칭찬을 들으면 어색해서 화제를 시계 얘기로 돌린다
- 도움이 필요할 때도 혼자 밤늦게까지 붙잡고 있다가 끼니를 거른다

## 작품 › 에피소드 › 챕터·이벤트 › 이벤트 '10년 만의 얼굴' › 진행 단계 1 › 일어나는 일
두 사람이 서로를 알아보고 첫인사를 나눈다
```

**(나) JSON:** 도구로 넣을 때 써요.
- **캐릭터:** `character-card/v2`
  - 빈칸 템플릿 `character-card-v2.template.json`을 채워요.
  - 항목별 형식은 캐릭터 카드 작성 가이드에 있어요. 3절이 항목 표이고, 4절 7번이 일과, 14번이 만남이에요.
  - 템플릿에 없는 선택 항목도 쓸 수 있어요: `appearance`, `routine[].place`, `relationship_stages[].mutual`(`true`/`false`), `openings`.
- **이야기:** 스튜디오가 편집하는 이야기 문서(`scenario-card/v1`, 에피소드 + 배역)
  - 템플릿 `scenario-card-v1.template.json`을 채워요. 항목별 형식은 시나리오 카드 가이드 3절에 있어요.
  - 메인의 이름을 그대로 써요. 서브는 엑스트라 목록의 첫 번째이고 `npc_id`는 `"sub"`이에요.
- **값의 모양**
  - 나이는 문자열(`"29"`)이에요.
  - 일과 시각은 `"HH:MM"`, 이야기 속 시각은 시간대 없는 `"2026-12-18T19:20:00"`이에요. JSON Schema 검사기의 `format` 검사(`time`, `date-time`)는 이보다 엄격하므로 끄고 검사해요.
  - 모든 ID는 영문 소문자나 숫자로 시작하고 영문 소문자·숫자·`_`·`-`만 써서 64자 이하로 해요. 문서 안에서 서로 달라야 해요.
  - `character_id`와 `scenario_id`는 스튜디오에 넣을 때 스튜디오가 붙인 ID로 맞춰요.
  - 다른 항목을 가리키는 항목(조건의 이벤트·표시·단계, 시작 장소, CG)은 문서 안에 있는 ID나 단계 이름만 써요.

### 9-4. 내기 전에 스스로 검사

에이전트가 확인할 수 없는 항목(검사 결과, 그림, 테스트)은 제작자에게 남겨요.

**캐릭터**
- [ ] 6-2 '캐릭터'의 글에 관한 항목을 모두 통과한다
- [ ] 필수 항목이 모두 있고 한도(예시 대화 2~6개, 만남 8개, 외모 800자, 만남의 시작 상황 1,000자)를 지킨다
- [ ] 일과가 하루를 덮고, 짧은 항목이 넓은 항목보다 위에 있다
- [ ] 분량이 AI가 읽는 글로 1,200~6,500자이고, 8,000자를 넘지 않는다(1-5)

**작품**
- [ ] 6-2 '작품'의 글에 관한 항목을 모두 통과한다
- [ ] 1-3의 표에서 '늘'·'화면만'인 항목을 다시 읽고, 결말을 미리 알려 주는 문장이 없다
- [ ] 모든 가리키는 항목(조건의 이벤트·표시·단계, 시작 장소, CG)이 문서 안에 있는 이름을 가리킨다
- [ ] 메인·서브·엑스트라·플레이어 기본 이름이 서로 겹치지 않는다
- [ ] 표정·상황, 의상, 장소, CG 이름이 한도 안이고 대괄호·콜론이 없다
