# 시나리오 카드 만들기 (`scenario-card/v1`)

> 스튜디오에서 작품을 만든다면 화면의 칸 이름으로 쓴 만드는 법: 캐릭터와 작품 가이드북을 먼저 보세요. 스튜디오의 에피소드와 배역은 저장할 때 이 시나리오 규격으로 합쳐집니다.

스토리 모드에서 플레이할 이야기를 만드는 방법을 정리했다. 결과물은 UTF-8 JSON 파일 하나다. 캐릭터 카드가 "누구인가"를 담는다면, 시나리오 카드는 "어떤 이야기인가"를 담는다. 같은 캐릭터 카드 위에 시나리오를 여러 개 얹을 수 있다.

## 2. 만드는 순서

2. **줄거리를 한 장으로 정리한다.**
   - 로그라인 한 줄
   - 챕터 2~4개
   - 챕터마다 본 이벤트 1~2개와 곁 이벤트 0~1개
   - 갈림길 하나
   - 끝 장에는 갈림길마다 다른 마무리 이벤트
3. 템플릿을 복사해 채운다. `[[…]]`를 모두 바꾸고, 필요 없는 항목은 지운다.
7. 직접 플레이해 보고 고친다. 고칠 때는 `version`을 올린다(`draft-1` → `draft-2`). 이미 시작한 이야기는 옛 버전을 계속 쓴다.

## 3. 필드별 쓰는 법

### 기본 정보

| 필드 | 쓰는 법 |
|---|---|
| `scenario_id` | 영문 소문자·숫자·`_`·`-`. 파일 이름이 된다 |
| `version` | 초안은 `draft-n`. 승인한 뒤 정식 버전 이름을 붙인다 |
| `title` | 40자 이내 |
| `logline` | 선택 화면과 AI가 본다. **결말이나 숨은 사실을 쓰지 않는다** |
| `follows` (선택) | 후속 이야기일 때 앞 이야기와 이어받을 엔딩: `{"scenario_id", "endings", "carry"}`. 그 엔딩으로 끝난 대화의 엔딩 카드에만 "이어지는 이야기"로 보인다. `carry`에 적은 앞 이야기 표지가 켜졌었다면 그 뜻이 "지난 이야기"로 넘어온다. 후속 이야기는 혼자 시작해도 말이 되게 쓴다 |

### 주연 (`lead`)

| 필드 | 쓰는 법 |
|---|---|
| `character_id` | 등록된 캐릭터 카드의 ID |
| `role_in_story` | 이 이야기에서 주연이 맡은 일과 사용자와의 관계. AI가 늘 본다. **"시계 안에서 쪽지가 나온다" 같은 앞일을 쓰면 AI가 2턴 만에 그 일을 꺼낸다** |
| `outfits` | 의상 목록. 첫 번째가 기본이다. AI가 답장에서 갈아입은 걸 보면 다음 턴부터 그 의상의 초상이 나온다. `detail`(선택, 80자)에 생김새를 한 줄 쓰면 상태창에 이름과 함께 보인다(예: "남색 바탕 나팔꽃 유카타, 머리를 올려 비녀를 꽂았다") |
| `expressions` | 표정 이름 목록. 첫 번째가 기본이다. AI는 이 이름으로만 `[이름:표정]`을 쓰고, 목록에 없는 표정은 기본 표정으로 바뀐다 |

### 조연 (`npcs`)

| 필드 | 쓰는 법 |
|---|---|
| `name` | 대사 태그에 쓰이는 이름. 12자 이내, `[` `]` `:` 없이 |
| `role`, `voice` | AI가 보는 설명과 말투 |
| `appearance` (선택, 400자) | 생김새. AI가 역할과 함께 읽고, 그림의 룩북이 이 글을 그대로 따른다. 비우면 AI가 역할에 맞게 정한다 |
| `secret` | **늘 가는 설명에 넣지 않는다.** 이 조연이 `cast`에 들어간 이벤트가 예약되거나 진행 중일 때만 메모로 AI에게 간다 |
| `secret_from` (선택) | 비밀이 처음 나올 수 있는 이벤트 목록(최대 4개, 모두 이 조연을 `cast`에 넣어야 한다). 그중 하나가 들어온 뒤로는 이 조연이 출연하는 장면마다 비밀이 간다. 비워 두면 출연하는 모든 이벤트에서 간다. 첫 장부터 출연하는 조연의 비밀을 뒤에 밝히려면 꼭 쓴다. 곁 이벤트는 안 열릴 수 있으니 뒤의 본 이벤트도 함께 적는다(예: `["sena_gossip", "festival_observation"]`) |
| `appears_from` | 이 이벤트가 들어오기 전에는 AI가 이 사람의 존재를 모른다. 끝 장에 처음 나와야 할 인물에 쓴다 |

### 무대와 사용자

| 필드 | 쓰는 법 |
|---|---|
| `world` | 어디서, 언제, 어떤 분위기에서 며칠 동안 벌어지는지 |
| `player.role` | 사용자가 맡은 사람. `{{{PLAYER_NAME}}}`은 사용자 페르소나의 호칭으로 바뀐다(뒤의 조사 은/는·이/가·을/를·와/과·랑·아/야도 맞춰진다). 예전 `{player}`도 그대로 쓸 수 있다 |
| `player.knows` | 사용자 인물이 처음부터 아는 것. 이야기에서 알아낼 것은 쓰지 않는다 |
| `player.default_name` | 이름을 안 정했을 때 쓰는 이름 |
| `style` | 시점(`first_person_player`: 사용자가 "나", 보고 듣는 것만 서술. `third_person`: 3인칭, 사용자를 이름으로 부름), 답장 길이(기본 1,000~1,600자) |

### 시작 (`start`)

| 필드 | 쓰는 법 |
|---|---|
| `at` | 이야기 속 시작 시각(`2026-12-18T19:20:00`). 실제 시간과 따로 흐르고, 앞으로만 간다. 캐릭터 카드의 영업시간·일과와 맞춘다 |
| `place_id`, `weather` | 시작 장소와 날씨 |
| `prologue` | 시작 전에 화면에만 보이는 글. 모델은 보지 않는다 |
| `situation` | AI가 아는 시작 상황. **두 사람이 서로 무엇을 알고 무엇을 모르는지, 오늘 처음 만나는지까지 쓴다.** 비워 두면 AI가 "지난번에 같이…" 같은 과거를 지어낸다 |
| `first_message` | AI의 첫 답장. 본문과 같은 형식(서술 + `[이름:표정] "대사"`)으로 쓴다. 문체의 본보기가 된다 |
| `active_events` | 시작부터 진행 중인 이벤트(보통 첫 장의 첫 이벤트) |

### 챕터 (`chapters`)

| 필드 | 쓰는 법 |
|---|---|
| `title` | 챕터 카드에 보이는 제목 |
| `min_turns` | 이 챕터에 최소 머무는 턴 수(보통 3~4) |
| `ends_with` | 이 중 하나가 해결되면 챕터가 끝난다. 갈림길마다 다른 마무리를 두려면 여러 개를 적는다. **마지막 장의 `ends_with`가 곧 엔딩이다.** 해결된 하나가 엔딩으로 고정되고, END 표지·에필로그·엔딩 카드가 이어진다 |

### 이벤트 (`events`)

| 필드 | 쓰는 법 |
|---|---|
| `kind` | `main`: 줄거리를 미는 일, 챕터를 끝낼 수 있다. `side`: 분위기를 더하는 작은 일 |
| `trigger` | `player`: 사용자의 말로 시작된다. `director`: 앱이 쉬는 틈에 불러와 AI가 연다 |
| `teaser` | 조건이 채워지면 상태창에 "곧 올지도"로 보이는 예고. AI도 방향으로 쓴다. **내용을 드러내지 않는다**(예: "뒤판이 생각보다 뻑뻑하다") |
| `requires` | `events_done`(먼저 끝나야 할 이벤트), `flags_all`(켜져 있어야 할 표지), `flags_none`(꺼져 있어야 할 표지), `stage_at_least`(관계 단계) |
| `setup` | 이벤트가 예약되거나 진행 중인 동안 AI가 메모로 계속 본다. **흔들리면 안 되는 사실(쪽지 문구, 이름)은 여기에 정확히 쓴다** |
| `milestones` | 순서대로 지나는 단계. 진행률은 "지난 단계 / 전체"로 보인다 |
| `milestones[].happens` | AI가 원문으로 확인하는 일. **눈에 보이는 행동으로 쓴다**(좋은 예: "두 사람이 쪽지를 함께 읽는다", 나쁜 예: "마음이 열린다") |
| `milestones[].guide` | 이 단계에서 AI가 갈 방향 |
| `milestones[].cg` | 이 단계를 지나면 그 자리에 고정되는 장면 그림 |
| `milestones[].choices` | 이 단계 직후 보이는 저자 선택지(최대 3개). **그대로 보낼 수 있는 말로 쓴다**(`"그 말, 종이 울릴 때 꼭 들을게요."`). 사용자가 고르거나 같은 뜻으로 쓰면 `sets_flags`가 켜진다 |
| `sets_flags` | 이벤트가 해결될 때 켜지는 표지 |
| `cast` | 이 이벤트에 나오는 조연. 그 조연의 `secret`이 이때만 AI에게 간다(`secret_from`이 있으면 그 이벤트가 들어온 뒤부터) |
| `at` | 이야기 속에서 이 일이 일어나는 때(`2026-12-24T23:40:00`). 이벤트를 불러오면 이야기 시계가 그때로 옮겨지고 시간 건너뛰기 표지가 붙는다. 축제 날, 사흘 뒤 같은 날짜가 정해진 장면에 쓴다. 쓰지 않으면 지금 흐름에서 바로 열린다 |
| `ending` (선택, 엔딩 이벤트만) | `{"title", "epilogue", "cg"}`. `title`은 엔딩 이름(없으면 이벤트 제목), `epilogue`는 AI가 에필로그를 쓸 방향(화면에 그대로 나오지 않음), `cg`는 엔딩 카드 그림(없으면 마지막 이정표의 CG) |

### 표지, 장소, 이미지

| 필드 | 쓰는 법 |
|---|---|
| `flags` | 분기에 쓰는 표지와 뜻. 선언한 것만 쓸 수 있다 |
| `places` | 장소 목록. `image`를 주면 장면 배너에 쓰인다. 목록 밖 장소도 이름으로 쓰일 수 있다(배너 없음) |
| `images` | `portrait`(인물·의상·표정), `background`(장소), `cg`(장면 그림). |

### 위젯 (`widgets`, 선택)

상태창에 작가가 정한 칸을 더합니다. 최대 6개이고, 플레이어도 이야기 중에 3개까지 더할 수 있습니다. 답장마다 AI가 바뀐 칸만 채웁니다(위젯 설계).

```json
{"widget_id": "teasing", "label": "놀림 게이지", "kind": "meter", "about": "lead",
 "instruction": "코하루가 지금 {player}를 얼마나 놀리고 싶어 하는지. 놀리면 오르고, 진심을 보이거나 당황하면 내려간다",
 "min": 0, "max": 100, "start": 40, "max_step": 15, "unit": "%"}
```

| 필드 | 쓰는 법 |
|---|---|
| `widget_id`, `label` | 영문 식별자(`p1`, `p2`…는 플레이어 몫이라 못 씀)와 화면 이름(16자) |
| `kind` | `text`(한 줄, `max_chars` 10~80), `meter`(정수 막대, `min`·`max`·`start`·`max_step`·`unit`), `list`(`max_items`·`item_chars`), `choice`(`options` 2~8개) |
| `about` | `lead`, `player`, `scene` 또는 조연 id. **`player` 칸은 사용자 본인의 말로만 바뀐다** |
| `instruction` | AI가 읽는 "무엇을 적을지"(200자). 오르고 내리는 조건을 함께 쓰면 잘 움직인다. AI는 읽지 않는다 |
| `to_actor` | 켜면 최신 값이 AI의 앱 메모에 한 줄로 간다. 기본 꺼짐(화면 전용) |

- 막대·보기·목록은 이번 턴에 실제로 나온 일로만 바뀌고, 막대는 한 턴에 `max_step`보다 많이 움직이지 않는다. 틀린 칸만 버리고 직전 값을 유지한다.
- "호감도" 같은 막대는 관계 단계와 따로 움직인다. 단계는 관계 규칙으로만 오른다. 관계 안의 다른 축(놀림, 긴장, 신뢰의 한 면)을 막대로 두는 편이 덜 어긋난다. 검사기가 경고한다.
- `player` 칸은 사용자 말이 근거라, 장면에서 남이 건넨 물건은 사용자가 받았다고 말해야 들어간다.

### 관계 (`relationship`)

| 필드 | 쓰는 법 |
|---|---|
| `stages` | 이 이야기에서의 관계 단계. `behavior`는 AI가 그 단계에서 하는 행동이고, `entry`는 AI가 다음 단계로 넘길 때 확인하는 조건이다 |
| `mutual` | 연인처럼 두 사람 모두의 말이 있어야 넘어가는 단계에 `true` |
| `start_stage` | 처음 단계 |
| `min_turns_in_stage` | 한 단계에 최소 머무는 턴 수(이야기 시간은 압축되므로 턴으로 센다) |
| `card_stages` (선택) | 작품 없이 돌린 이야기에서 엔딩 뒤 "메신저로 이어 가기"를 할 때 이 이야기의 단계가 이어질 주연 카드의 단계(작품의 이야기는 엔딩 뒤 DM으로 이어지지 않아 쓰이지 않는다): `{"설레는 사이": "마음이 쓰이는 사이"}`. 없으면 같은 이름, 그것도 없으면 단계 사다리의 같은 높이에서 시작한다. 검사가 카드에 없는 단계를 거절하고, 대응되지 않는 단계를 경고한다 |

`inner_thought`: `peek`(기본, 엿보기 버튼), `shown`(항상 보임), `off`(안 보임).

## 5. 잘 쓰는 법 (점검에서 배운 것)

1. **스포일러는 `secret`과 `setup`에만 쓴다.** `logline`, `role_in_story`, `world`, `teaser`, 조연 `role`에 앞일의 단서를 쓰면 AI가 먼저 꺼낸다.
   첫 장부터 나오는 조연의 비밀은 `secret_from`으로 공개할 이벤트를 정한다. 검사기는 첫 장에 출연하는 조연의 비밀에 `secret_from`이 없으면 경고한다.
2. **갈림길에는 기본 경로를 둔다.** 갈래 A는 `flags_all: [a]`, 갈래 B는 `flags_all: [b]`, 어느 것도 고르지 않은 경우는 `flags_none: [a, b]`로 막다른 길을 없앤다. 검사기는 모든 마감 이벤트가 표지를 요구하는 챕터를 경고한다.
3. **이정표 `happens`는 눈에 보이는 일로 쓴다.** 그 일이 답장에 실제로 쓰여야 단계가 넘어간다.
4. **핵심 사실은 `setup`에 정확히 쓴다.** 쪽지 문구가 `setup`에 있으면 AI가 매 턴 그대로 쓴다. 없으면 장면마다 문구가 바뀐다.
5. **`situation`에 "처음 만난다"와 "모르는 것"을 쓴다.** 비워 두면 AI가 없던 과거를 채운다.
6. **본 이벤트는 챕터마다 1~2개로 둔다.** 곁 이벤트가 많으면 이야기가 흩어진다.
7. **날짜가 정해진 장면에는 `at`을 단다.** 로맨스 첫 점검에서 "축제 사흘 전 밤"의 장면이 첫날 밤에, 축제 자정이 엿새 이른 날에 열렸다. `setup`에 날짜를 써도 앱은 그 날짜를 모른다.
8. **캐릭터 카드의 정해진 사실과 맞춘다.** 영업시간, 가족, 일하는 방식이 다르면 AI가 둘 사이에서 흔들린다(예: 금요일 영업은 19시까지 → 이야기 시작 19:20).
9. **연인 단계는 `mutual: true`로 둔다.** 그러면 한쪽의 말만으로는 넘어가지 않는다. 주연이 먼저 고백하지 않는 성격이라면 `behavior`에 그렇게 쓴다.
10. **이미지가 없어도 된다.** 자리표시 그림으로 먼저 플레이해 보고, 표정과 장면이 정해지면 그림을 넣는다. 앱이 그리게 할 때는 주연 카드의 `appearance`와 조연 `appearance`를 먼저 채운다. 비워 두면 AI가 외모를 지어낸다.

## 6. 체크리스트
