# 라프티 스튜디오 작품 만들기

작가는 이야기를 정하고, 칸은 이 스킬이 채웁니다. 라프티의 작품에는 칸이 많습니다. 작품 하나에 값이 500개쯤 들어가고, 그중 절반은 ID와 참조처럼 작가의 창작이 아닌 배선입니다. 작가가 그 칸을 보지 않게 하는 것이 이 스킬의 일입니다.

## 작가에게 말하는 법

작가는 개발자가 아닐 수 있습니다. 칸 이름, ID, JSON, 스키마 같은 말을 쓰지 않습니다. 이벤트는 「장면」, 이정표는 「꼭 일어나는 일」, 챕터는 「장」으로 말합니다. 진행 상황은 한 줄로 알립니다. 파일 내용을 대화에 펼치지 않습니다.

## 전체 흐름

어디서 출발하든 `작품설계서.md` 하나로 모입니다. 작품 파일은 설계서에서만 만듭니다.

```
소설 원고 ───────┐
lafty-novel 결과 ─┼─▶ 작품설계서.md ─▶ 작가 승인 ─▶ 칸 채우기 ─▶ 검사 ─▶ 제목.lafty.json + 제목 그림 태그.md + 확인할 것.md
아이디어 ────────┘
```

작업 폴더는 지금 폴더 아래 `{제목}/`로 잡고, 설계서와 `work/`를 그 안에 둡니다. 지금 폴더에 그 작품의 설계서가 이미 있으면 그 폴더를 그대로 씁니다.

참고 문서가 「8장」, 「4-4」처럼 장 번호로 가리키면 `guide-basics.md`(1장), `guide-character.md`(3장), `guide-work.md`(4장), `guide-pictures.md`(5장), `guide-check.md`(6-2, 7장), `rating.md`(8장), `guide-agent.md`(9장)에서 찾습니다.

### 1. 입구 고르기

| 받은 것 | 할 일 |
|---|---|
| `작품설계서.md` | 2단계는 건너뛰고 형식만 확인합니다. 절 제목과 표 머리가 `references/story-sheet.md`와 같은지, 1절의 「만들 것」과 12절이 있는지 봅니다 |
| 소설이나 원고 | `references/reading-a-novel.md`를 읽고 설계서를 뽑습니다 |
| 설정 메모, 아이디어 | `references/questions.md`를 읽고 질문합니다 |
| 만들어 둔 `.lafty.json`을 고치기 | 그 파일을 읽고 요청한 곳만 고친 뒤 4단계로 갑니다 |
| 스튜디오에 이미 있는 캐릭터로 새 작품이나 후속작 | 그 캐릭터의 이름을 스튜디오에 적힌 그대로 받고, 위의 입구 하나로 설계서를 씁니다. 칸을 채울 때와 올릴 때는 `references/mapping.md`의 「이미 있는 캐릭터의 작품」을 따릅니다 |

### 2. 작품설계서 쓰기

`references/story-sheet.md`의 틀을 그대로 씁니다. 등급과 쓸 수 없는 것은 `references/rating.md`를 먼저 읽습니다. 쓸 수 없는 소재가 있으면 이 단계에서 말합니다.

### 3. 작가 승인 받기

설계서를 파일로 저장하고, 대화에는 아래만 짧게 보입니다. 긴 설계서를 다 붙이지 않습니다.

- 메인, 사용자의 자리, 장의 흐름, 엔딩을 다섯 줄 안팎으로
- AI가 채운 내용
- 제작자가 정할 내용(질문, 선택지, 추천)

**승인 전에는 칸을 채우지 않습니다.** 방향이 틀렸을 때 잃는 것이 가장 크기 때문입니다. 작가가 「그냥 해 줘」라고 하면 추천대로 정했다고 알리고 넘어갑니다.

### 4. 칸 채우기

`references/mapping.md`를 읽습니다. 설계서가 칸으로 가는 길과, 테스트 플레이에서 배운 규칙이 있습니다. 아래 순서로 조각을 `work/` 폴더에 씁니다. 한 조각씩 쓰고 다음으로 갑니다.

1. `work/character.json`: `references/guide-character.md`. 일과, 만남, 예시 대화의 세부는 `references/card-guide.md`
2. `work/info.json`, `work/derivative.json`, `work/notes.json`: 태그는 `references/work-tags.md`의 목록에서 먼저 고릅니다
3. `work/story.json`: `references/guide-work.md`. 항목마다 쓰는 법의 세부는 `references/scenario-guide.md` (스토리가 있을 때만)
4. `work/pictures.json`: `references/picture-tags.md`. 그림마다 사진 탭에 붙여 넣을 태그입니다. **그림은 그리지 않습니다.** 이미지를 만드는 도구가 있어도 같습니다.

상태창 칸(`widgets`)은 작품의 재미에 직접 쓰일 때만 3번에 넣습니다.

**캐릭터만 만들 때는** 1번, `work/notes.json`, 4번만 씁니다. `work/info.json`, `work/derivative.json`, `work/story.json`은 두지 않습니다. 작품 정보가 있으면 스튜디오가 스토리 없는 작품을 하나 더 만듭니다.

빈 틀은 `assets/*.template.json`, 완성된 예는 `assets/example-work.lafty.json`입니다. 예시는 길어서 필요한 부분만 찾아 읽습니다. 예시의 문장을 베끼지 않습니다. 칸 형식의 정본은 `assets/*.schema.json`입니다.

### 5. 검사하고 고치기

```bash
python scripts/pack.py work/ 제목.lafty.json
```

`pack.py`가 숨은 ID를 맞추고 파일 하나로 합친 뒤 검사합니다. 그림 태그는 파일의 메모에 함께 넣고, 파일 옆에 `제목 그림 태그.md`를 만듭니다. 스크립트는 어디서 불러도 됩니다. 스킬 폴더의 경로로 부릅니다.

- 「수정할 항목」은 0개가 될 때까지 고칩니다. 형식 오류를 고치면 내용 검사가 이어서 돌아 새 항목이 나올 수 있습니다.
- 「확인할 항목」은 하나씩 읽고, 의도한 것이면 남깁니다.
- 스크립트를 실행할 수 없는 환경이면 조각을 한 JSON 파일로 합쳐 내고, `references/guide-agent.md`의 9-4를 손으로 따라갑니다.

그다음 `references/guide-check.md`의 게시 전 체크리스트에서 글에 관한 항목을 스스로 확인합니다. 가장 중요한 네 가지입니다.

1. **앞일이 새는 곳:** 설계서의 진실표를 한 줄씩 들고, 늘 보이는 칸(`references/guide-basics.md` 1-3)을 다시 읽습니다. 소개글, 역할, 무대, 장 제목, 예고 문구도 봅니다.
2. **결정적 한 수:** 꼭 일어나는 일의 주어가 메인이라 사용자의 할 일이 사라지지 않았는지 봅니다.
3. **꼭 보여야 할 장면:** 설계서의 필수 장면이 메인 장면이고 조건이 막혀 있지 않은지 봅니다.
4. **이야기의 길이:** 꼭 일어나는 일이 한 번 놀 때 16~22개인지 봅니다. 한 개에 2~4턴이 들어 이 정도면 50~80턴입니다.

### 6. 전달하기

세 파일을 줍니다.

- `제목.lafty.json`: 스튜디오에 올리는 파일입니다.
- `제목 그림 태그.md`: 사진 탭에서 그림마다 붙여 넣을 태그입니다.
- `확인할 것.md`: AI가 채운 내용, 제작자가 정할 내용, 비워 둔 작가 쓰기 자리, 넣어야 할 그림 목록, 테스트에서 볼 것, 게시 창에 쓸 글입니다. 앞의 둘은 설계서 12절과 `work/notes.json`의 `invented`, `to_decide`와 같은 말로 씁니다. 게시 창에 쓸 글은 `references/mapping.md`의 「게시 창에 쓸 글」을 따릅니다.

작가에게 다음을 알립니다.

1. 스튜디오 「만들기」 위쪽의 「라프티 파일 불러오기」로 올리면 비공개 초안으로 들어갑니다. 내가 쓴 글이거나 쓸 권리가 있는 글이라고 작가가 확인해야 합니다. 게시는 작가가 합니다. 이미 있는 캐릭터의 작품이면 이 길로 올리지 않습니다(`references/mapping.md`의 「이미 있는 캐릭터의 작품」).
2. 작품이면 스토리 테스트를 엔딩까지 한 번 합니다. 캐릭터만이면 캐릭터 편집의 DM 테스트로 여러 번 말을 걸어 봅니다. 검사를 통과해도 실제로 대화해 봐야 보이는 문제가 있습니다.
3. 그림은 파일에 들어가지 않습니다. 스튜디오의 사진 탭에서 `제목 그림 태그.md`의 태그로 그려 갤러리에 넣습니다. 순서는 가이드 5-5에 있습니다.
4. 스튜디오가 수정할 항목을 알려 주면 「AI에게 줄 문구」를 받아 파일을 고칩니다. 항목의 위치가 함께 옵니다.
5. 테스트 뒤 수정할 항목을 말해 주면 파일을 고쳐 다시 만듭니다. 이미 올린 작품은 작품 편집 머리글 ⋯ 메뉴의 「파일로 불러오기」로 올립니다. 새로 가져오면 작품이 하나 더 생기고 넣어 둔 그림이 이어지지 않습니다. 표정, 장소, 장면 그림의 이름을 바꾸면 그 그림이 끊기니, 고칠 때 이름은 그대로 둡니다.
6. 「파일로 불러오기」는 메인 캐릭터의 카드를 그대로 두고 작품 정보와 이야기만 바꿉니다. 카드를 고쳤다면 창의 「캐릭터 카드도 바꾸기」를 켜야 카드도 바뀝니다. 바뀐 카드는 게시하면 그 캐릭터의 DM과 그 캐릭터가 나오는 다른 작품에도 들어가니, 카드를 고친 까닭을 함께 알립니다.
7. 캐릭터만 올린 파일은 다시 불러올 곳이 없습니다. 고칠 것은 스튜디오의 캐릭터 편집에서 직접 고칩니다. 아직 게시하지 않았고 그림도 넣기 전이면, 고친 파일을 새로 가져온 뒤 앞의 캐릭터를 지워도 됩니다.
8. 캐릭터와 작품의 게시 창에는 파일에 없는 칸이 있습니다. `확인할 것.md`의 「게시 창에 쓸 글」을 붙여 넣습니다.

## 지키는 것

- 사용자의 감정과 결정을 정하지 않습니다. 캐릭터 카드에는 사용자의 이름과 과거를 쓰지 않습니다. 사용자가 맡는 역할의 과거가 이야기에 필요하면 역할과 프롤로그에만 씁니다. 사용자를 부르는 자리는 `{{{PLAYER_NAME}}}`만 씁니다.
- 앞일은 앞일 칸에만 씁니다.
- 작가가 주지 않은 설정은 AI가 채운 내용으로 적습니다.
- 규격에 없는 칸을 만들지 않습니다. 필요한 내용은 가장 가까운 칸에 산문으로 넣습니다.
- 글로 상태창을 출력하라는 지시, 글자 수 강요, 출력 형식, 그림 코드, 「AI처럼 굴지 마」 같은 지시를 어느 칸에도 쓰지 않습니다. 앱이 하는 일입니다.
- 그림을 직접 그리지 않습니다. 이미지를 만드는 도구가 있어도 쓰지 않고, 태그로 넘깁니다(`references/picture-tags.md`).
- 자유 모드 작품은 만들지 않습니다. 이 스킬의 파일은 라프티 모드 작품이나 캐릭터로 들어갑니다. 작가가 자유 모드를 원하면 스튜디오에서 작품 프롬프트를 직접 쓰는 방식이라고 알리고(`references/guide-work.md` 4-7), 라프티 모드로 만들지 묻습니다.
